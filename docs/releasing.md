# 发布方式

1. 在仓库根目录运行 `python3 scripts/validate.py`，查看 CI 是否通过。
2. 更新 [CHANGELOG.md](../CHANGELOG.md)，区分工具整理、行为变化与实机验证。
3. 提交源码、使用说明与许可，使用 `v<主版本>.<次版本>.<修订号>` 标签创建 GitHub Release。
4. 发布包保留源码、第三方许可和每个工具的说明。大型镜像按板型作为独立附件附带 SHA-256，不放入 Git 历史。

本项目的 CI 仅做离线验证，不连接或部署到机器人。现有装配工具的在线站点继续由原 `microduck-servo-guide` 仓库维护；这里的标定网页通过 Python 在本地运行，不能用静态站点托管替代后端。
