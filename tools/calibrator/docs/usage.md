# 逐关节标定与维护使用说明

适用带有兼容 robotd 维护接口的 15 舵机 HD1910 MicroDuck，串口波特率 1 Mbps，身体方向全部 −1、嘴部独立双端点配置。界面在电脑上运行。兼容性和当前验证边界见 [项目说明](../README.md#适用范围)。文中 `robot.local` 和登录用户名是示例，使用前替换为实际值。所有 `./run.sh` 命令均在仓库根目录执行。

工具解决“全身同时摆零位”的困难：摆正一颗 → 稳定采样 → 保存这一颗的零位 → 可选单独使能保持 → 下一颗。已经使能的关节保持在刚确认的位置。完成后可另行点击“全部回零并保持”检查整体。不会让 robotd 进入 HOME 或启动模型。

## 启动

### Zero 3W（仅 EEPROM 模式）

```sh
./run.sh --ssh radxa@robot.local --eeprom-only
```

此模式继续把手动摆正的机械零位写进所选舵机 EEPROM，使该位置读数为 2048；不读取或写入 TOML、旧机 JSON 等机器人标定配置文件。原始寄存器与操作日志仍完整备份。断力检查使用现有 `robot.busStatus` 的新鲜 native 反馈；串口只在用户进入标定、停止原控制服务并确认独占后打开。结束时先断力核验，再恢复原服务。

身体关节可直接逐颗采样和保存。因不加载旧嘴部配置，嘴部仍需在本次会话手动采样闭合、张开两端点；完成后才能使用“全部回零并保持”。嘴部端点随会话备份，不写入机器人配置。原有限速、低力保持与保护逻辑保持不变。

远端只读预检：`sudo python3 agent.py --serial-port /dev/ttyS2 --check`，不停止服务或打开串口。

### 树莓派（兼容 JSON 配置模式）

电脑需要 Python 3.10+，无第三方 Python 依赖。默认只运行模拟舵机：

```sh
./run.sh --demo
```

打开 <http://127.0.0.1:8795/>。模拟模式不会连接、写入真实小鸭。点“开始模拟标定”后可演练保存、保持、释放、撤销、嘴部两个端点和导出记录。

准备实机首测时，先结束模拟服务器（Ctrl+C），在小鸭上电联网后运行：

```sh
./run.sh --ssh user@robot.local
```

需电脑已有 SSH 密钥登录、远端 Python 3.10+、`sudo -n python3` 与 systemd。启动网页不连接串口；先点击“检查环境与发现串口”，自动检查/准备 pyserial、fuser 并列出串口。多候选时明确选择；默认 auto 优先匹配 robotd 端口。准备过程不停止控制服务，失败不会进入标定。“SSH 环境检查日志”实时显示 SSH 连接、临时文件上传、依赖检查与安装、串口发现结果；错误后保留输出，并同步写入电脑会话目录的 `setup-stderr.log`。点“连接并进入标定”后才进行维护；准备与代理上传至 `/tmp/duck-calibrator-<hash>-<random>/`。这不会升级 robotd 或安装常驻服务。离线环境可加 `--no-install-deps`，详见 [连接说明](../README.md#连接实机)。

## 操作

1. 先完成环境检查并选择串口，再按手柄 Select，确认断力。将躯干固定在支架上，腿和头部留出空间。机械零位不适合落地承重。
2. 进入标定后工具确认 15 个反馈新鲜、全断力，备份原值，暂停手柄、padd、updaterd、robotd，独占串口。标定期间手柄 Select 不可用；使用本页“全部断力”，通信异常则托稳后关主电源。
3. 选 ID，看高亮关节。页面自动聚焦对应腿部或头颈：俯仰切到侧面、侧摆切到正面、转向切到斜上方。可拖动或切换手动视角，选择下一颗时恢复自动视角；点击“自动视角”也可随时恢复。参照其两侧结构和装配标记手动摆到 **机械 0°**，其余断力关节可随意放松。3D 的 0°、HOME、±10° 按钮只改参考画面，不发动作。
4. 保持这颗不动，点“采样当前机械零位”。采样 20 次、约 0.8 秒，波动不超过 4 计数。预览偏移变化，30 秒内点击“保存这一颗零位”。保存只写它的 EEPROM 31–32，然后锁回；其余零位不变。
5. 可选：继续保持在刚确认的位置，手离开舵盘及连杆，勾选确认并点“使能这一颗保持”。若已偏离位置超过 4 计数，拒绝使能，提示手动摆回；**不驱动关节回零**。
6. 接着标定下一颗；上一颗可以继续保持。修改或撤销某颗零位前，必须先释放这一颗。撤销仅还原本次会话进入时该 ID 的零位。
7. 嘴部 ID34 单独采样自然闭合和舒适张开；保存后更新嘴部配置。不会拿身体 0° 模型覆盖嘴部行程，3D 资产没有嘴部转轴动画。嘴部使能保持在刚采样的张开端点。
8. 全部完成后，在“整体零位检查”勾选确认，再点“全部回零并保持”。已在上次会话标定的关节可沿用，不必重做全部15颗。躯干固定在支架上，双腿悬空、头颈及嘴有活动空间，手离开关节。先逐颗以当前位置使能，再将15颗目标缓慢移到2048；嘴部2048是实测闭合零位。**这是实机动作，3D参考按钮仍不发动作。**
9. 回零途中可点顶栏“全部断力”或“停止并全部断力”，取消后不会自动继续。到位后显示最大实测误差，每颗目标和角度可在表格核对。保持力不足或卡住会取消归零并尝试全部断力，不提高扭矩强推。
10. 点“结束并恢复服务”：先全部断力、恢复临时参数，再释放串口、启动原本运行的 robotd；核验 15 颗断力后恢复原本运行的手柄等服务。HOME 与行走测试由用户之后另行操作。

不必每次标定全部 15 颗；可只复核可疑关节。不能把承重 HOME 的读数保存成机械零位，也不能用新零位掩盖舵机跟随误差、支架形变或 IMU 安装偏差。

## 悬空交替踏步脚本与日志

`run-gait-test.sh` 是电脑侧入口，`gait_test.py` 包含计划、实机维护端、SSH 心跳、离线模拟和日志。需要同目录的 `core.py`、`storage.py`、`agent.py`、`board_setup.py`。不升级固件或安装常驻服务，实机程序临时上传到 `/tmp/duck-gait-test-<随机>/`。

先固定躯干、双腿完全悬空，给连杆留出空间，Select 断力，手离开关节。结束现有网页标定会话后，在电脑交互终端执行：

```sh
./run-gait-test.sh --ssh radxa@robot.local --serial-port /dev/ttyS2 --supported
```

`--supported` 表示上述现场条件已经满足。程序先核验全断力、备份原始寄存器，暂停原来运行的控制服务并独占串口；连续五次完整身份/参数/反馈检查通过后，倒计时五秒才接入当前姿态保持，然后缓慢到 HOME 参考姿态。先以半幅完成左右各一次踏步，再以全幅完成两轮。全幅相对 HOME 的膝幅度 12°、髋 8°、踝 4°，镜像折腿以保持模型足端俯仰，模拟原地踏步。髋转向和侧摆保持 HOME。头颈和嘴保持断力。它没有落地行走的平衡控制，只适合悬空观察，不是力矩测量。

默认速度上限 3°/秒、单次目标增量不超过 4 计数；P/D/I 保留进入时实际值，临时输出上限最多 300/1000，保留原有更低上限。跟随偏差超过约 2°会暂停目标，持续三秒则停止；超过约 4°立即停止。温度达到 48°C、舵机上报电压低于 6.5V 或高于 8.4V、通力/目标/参数/EEPROM/锁发生非预期变化、读取或校验失败也停止。这些是该实验程序的门槛，不是厂家性能规格。总运行时间最多 180 秒，不会网络延迟后追赶目标，不重试运动写入或忽略读取超时。写目标后先读回确认，再允许显式使能，避免丢写后启用旧目标。

运行终端按 **回车或 Ctrl+C** 请求停止。启动时清除终端里残留的输入换行，上传命令不读取终端输入；只有之后新输入的回车才触发停止，EOF 不会被误当作回车。日志会记录 `keyboard:Enter`、`local_signal:SIGINT`、`local_timeout:220s` 等电脑端停止来源，远端区分 STOP、输入关闭和心跳超时。如果在进入维护前取消，不访问机器人、不执行假清理，日志将断力状态记为未检查，而不是“已确认断力”。这个脚本独占串口时，手柄暂停；8795 网页的停止按钮不控制此独立脚本。控制端心跳超过两秒中断时，板端请求退出；结束和异常均逐颗尝试全部断力、恢复原 RAM 参数，然后按原顺序恢复服务。软件断力未确认或串口/内核失效时，日志会明确标为失败/未知，不能当作硬件急停。不要在测试过程中切换到手柄或另一网页控制器。

命令第一行显示本次日志目录，默认 `~/.microduck-gait-tests/<时间>-<随机>/`，每次独立保存：

- `run.log`：带时间的可读进度、失败和清理状态。
- `samples.csv`：每帧每颗腿部舵机的目标/实测角度、误差、电压、温度、P/D、输出上限和采样耗时。
- `events.jsonl`：包括每个阶段和完整逐帧数据的事件流，失败时也保留已写记录。
- `summary.json`：是否完成、是否确认全断力/恢复服务、各关节最大跟随误差和最低电压。
- `plan.json`、`stderr.log`：实际计划与远端错误。`load_raw`、`current_raw` 是未换算的寄存器原始字，不能视为实测电流或力矩。

**Zero 本机直跑**：将这五个 Python 文件放在同一个目录，在已登录 Zero 的交互终端执行 `sudo python3 /目录/gait_test.py --onboard --supported`。该模式直接运行板端维护循环，不需要电脑进程、二次 SSH 或 stdin 心跳。仅 Ctrl+C、SIGTERM/SIGHUP、终端关闭、反馈异常和超时会请求退出；普通回车不会取消。终端必须保持打开，不能用 `nohup`、后台运行或重定向 stdin。通过 sudo 启动时，默认日志写到原登录用户的 `~/.microduck-gait-tests/` 下，每次新建时间和随机标识目录。其他运动、限幅、校验、备份、断力和恢复流程与电脑模式相同。上传或 `--onboard --plan` 只准备/查看程序，不启动动作。

只看计划：`./run-gait-test.sh --plan`。离线演练：`./run-gait-test.sh --demo`，采用虚拟时间和模拟跟随，不连接机器人，也不能验证实机精度。较小幅度可用 `--lift-deg 8 --cycles 1`；更大的膝幅度允许到 `--lift-deg 15`（髋 10°、踝 5°），总计划始终检查现有关节范围。日志目录可用 `--log-dir /绝对路径/新目录` 指定，已有目录拒绝覆盖。

验证：`python3 -m unittest -v test_gait_test.py`。新测试覆盖左右镜像、写入范围/单步上限、原参数与低输出上限保留、运动中停止、低压、卡住、丢写、读取失败、日志断开和恢复失败。

## 保持策略与故障处理（手动标定与整体归零）

- 保存不会自动使能。使能只能来自当前关节的明确按钮操作，且该关节必须已在当前会话标定。
- “全部回零并保持”是另一个明确动作：必须勾选全部零位已核对（包括沿用）、支架稳固、手已离开；不要求全部在本次会话重新标定。目标直接为舵机内部坐标2048，不再次叠加 EEPROM 偏移，原零位不改写。身体配置文件只核验 EEPROM 与保存记录一致；嘴部配置还保存实际行程端点。
- 归零每次状态请求只执行一个有限步骤：先逐颗预载当前角度，再按最高5°/秒、单步最多12计数（约1.05°）调整全部目标，网络延迟不会累积成大步跳转。界面归零时约200毫秒轮询，其他操作暂停，断力按钮始终可用；串口事务失败可能延长响应，因此它仍不是硬件急停。到达2048且所有反馈连续3次在12计数内才报告到位。反馈与当前目标偏差超过约4°、超出当前候选关节范围、任一故障/过热/通信失败或180秒未完成时取消归零并尝试全断力。
- 身体保持临时用 P5/D20，嘴部 P10/D20，扭矩上限寄存器 300（满量程 1000）。**这是待实机验证的低扭矩保持档，不保证足以支撑整机，也不是 30% 电流的测量值。** 释放后恢复会话最初读到的 P、D、扭矩上限。I、运行模式、方向、机械限位、IMU 与模型不变。
- HD1910 mode 4 写目标本身可能使能。因此先写并核验低扭矩/P/D，再读取位置，只有位置稳定才写刚读到的位置。不会用旧目标、2048 广播目标或 HOME 目标使能。
- 保持中每 3 秒轮询，检查全体身份、零位、锁、通力、故障、温度、电压，以及保持误差不超过约 4°。这不是实时运动控制器或独立硬件急停。
- 任一请求发生异常，远端尝试对全部 15 个 ID 分别断力；一颗失败不会跳过其他 ID。断力确认后恢复临时参数。无法核验则提示托稳、切断主电源，不自动恢复控制服务。
- 页面约 10 秒无心跳时本地端结束会话；即使电脑与小鸭失联，远端约 12 秒无请求也会执行清理。切换到长期后台、电脑休眠或关闭页面会结束保持。远端被强杀、内核/总线故障时，软件无法保证断力。
- 写零位或配置失败时尝试读回回滚该 ID；写入超时不会自动重放。对异常状态，先检查记录，不能把“超时”当成“未写入”。
- 释放不恢复旧目标寄存器 42–43，避免意外使能；后续 robotd 正常 Start 流程会预载有效当前姿态。

## 备份与恢复

- 小鸭原始寄存器、原标定文件、服务状态、当前版本链接与逐步日志：`/opt/robot/calibration-backups/<时间>-<随机>/`。
- 电脑模拟/实机交互记录：`~/.microduck-calibrator/<时间>-<随机>/`，可用 `--data /path` 指定目录。网页“导出本次记录”包含模式及事件；实机会话首次应答包含原始 15 个寄存器表与原标定文件。
- 当前会话“撤销本次零位”仅恢复选中关节。软件重启后不会猜测哪个历史备份应写回，不提供无预览的跨会话一键覆盖；保留备份供明确选定后的维护恢复。
- 现有 `/etc/robot/hd1910-body-calibration.json` 存在则核验并同步更新；原版本没有这个文件时不新增。嘴部使用已有 `/etc/robot/hd1910-mouth.json`，不改其余关节。
- 异常清理没有成功恢复服务时，先断电；下一次上电后检查相关服务与日志，再连接工具。工具不修改开机 enable 状态，不执行 EEPROM 出厂重置。

## 树莓派独立归零脚本

如果已在板端另行安装 `duck-zero` 包装命令，可在树莓派交互终端执行 `sudo duck-zero`。本仓库不会自动安装这个命令。没有包装命令时，使用下面的 `zero.py` 入口。远程运行已安装的包装命令：

```sh
ssh -t user@robot.local sudo duck-zero
```

先结束网页标定会话、Select 断力，将躯干固定、双腿悬空、头颈嘴留出空间。脚本会展示本轮参数，输入 `ZERO` 才开始。若已经确认准备好，可加 `--supported` 直接开始。归零和保持过程中按回车或 Ctrl+C 结束，随后核验全断力并恢复原服务；手柄在此期间暂停。

源文件是 `zero.py`，与 `agent.py`、`core.py`、`storage.py`、`board_setup.py` 放在同一目录，在板端用 `sudo python3 zero.py` 运行，依赖树莓派现有 pyserial。`sudo duck-zero --check` 只读检查 robotd 反馈和全断力状态，**不停止服务、不打开串口、不发送动作**。离线模拟：`python3 zero.py --demo --supported --hold-seconds 1`。

脚本在树莓派本机每轮约100毫秒加总线事务耗时推进，不依赖网页心跳。身体临时 P5/D20、扭矩上限最多681，嘴 P10/D20、最多300，均不提高进入会话前原有的更低上限；可选 `--torque-limit 300`。速度默认3°/秒，可选 `--speed 1` 至 `5`；所有目标为舵机内部2048，不重写EEPROM，不叠加软件零位偏移。现有身体标定文件只核验EEPROM一致，嘴部文件还定义开合端点。

跟随偏差大于约2°时暂停推进全部目标，给舵机最多3秒追上；到达最终目标时要求约1°内稳定3次。超过4°仍立即中止；通信、范围、温度、电压检查沿用维护代理。错误会打印实际位置、目标、PD、扭矩上限及电压，以区分跟随不足与标定问题。到位后默认保持最多120秒，可用 `--hold-seconds` 改为不超过300秒；到时断力恢复服务。SSH挂断/信号会请求退出，但总线/内核故障或被强杀时软件无法保证断力。

网页仍保留300档；独立脚本的681档不是对实际 ID30 问题已解决的保证。不要因为报错就清除舵机内部偏移或提高机械力强推。

## 验证

```sh
cd tools/calibrator
```
